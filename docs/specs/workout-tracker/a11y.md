# Live workout tracker: accessibility audit of the whole flow

**Scope**: the live tracker on `feature/workout-tracker-redesign` (working tree, 6 Oct 2026).
Files: `WorkoutTrackerView.swift`, `InlineRestTimerRow.swift`, `ProgressionNote.swift`,
`ExerciseTrackerView.swift`, `SetTrackerView.swift`, `SetTrackerRowView.swift`,
`SetKeyboardView.swift`, `SetKeyboardTextField.swift`, plus the presenters they call
(`WorkoutTrackerPresenter+ActiveExercise/+Rest/+Finish`, `SetTrackerRowPresenter`,
`SetKeyboardPresenter`, `ActiveWorkoutState`) and `CompoundUITests/WorkoutTrackerUITests.swift`.
**Standard**: WCAG 2.2 AA, plus the HIG where it is stricter (44 pt targets, 11 pt text).
**Method**: I read the code only. I ran nothing on a device or simulator, so this audit
**did not** include VoiceOver, Switch Control, Voice Control, AX5 or contrast measurement on a
device. Contrast ratios are worked out from the iOS light-mode system colours. Anything that
depends on runtime behaviour is marked *(verify)*.

`grep` over the tracker and the design system finds exactly **one** accessibility notification
(`WorkoutTrackerPresenter+Finish.swift:56`, the quick-finish announcement). It finds **no**
`AccessibilityFocusState`, `accessibilityAction`, `accessibilityRotor`,
`accessibilityInputLabels` or `.isKeyboardKey`. Most of the findings below follow from that.

## Findings, by severity

### Critical

**C1. VoiceOver loses focus at every step of the main loop (log → rest → skip → log → next exercise).**
WCAG 2.4.3 Focus Order, 4.1.3 Status Messages.
- `WorkoutTrackerView.swift:60-97`: the bottom bar is `if restEnd { HStack { CTA(Skip Rest); +15s } } else if … { CTA(log) }`. These are two different view identities. Each log and each rest end destroys the focused element, and VoiceOver focus jumps to an unpredictable place, often the top of the screen *(verify)*.
- `SetTrackerView.swift:76`: a warm-up is filtered out of the table once it is logged. A VoiceOver user who logs a warm-up from its own Done button loses the element they are on.
- `WorkoutTrackerView.swift:196` with `+ActiveExercise.swift:24-31`: tapping an Up Next row moves that exercise onto the card, so the row disappears from under focus. The list does not scroll to the card either.
- Nothing calls `AccessibilityFocusState` anywhere.

**Fix**:
- Keep one `CallToActionButton` whose label and action switch between Log, Skip Rest, Next and Finish. Keep "+15s" as an optional sibling outside that button.
- Bind `@AccessibilityFocusState var focus: Focus?` with cases `.cta` and `.cardTitle`:
  - After `onPrimaryActionPressed`, set `focus = .cta`.
  - After `onExerciseSelected`, `onDoLaterPressed` and the `.next` action, use a `ScrollViewReader` to scroll the card to the top, then set `focus = .cardTitle`.
- Leave a logged warm-up in place, or move focus to the next row before removing it.

### Serious

**S1. State changes are not announced.** WCAG 4.1.3 Status Messages.
- Logging (`+ActiveExercise.swift:239-272`) plays `.success` haptic and nothing else.
- Rest end (`+Rest.swift:108-118`) plays a sound **only if** `restTimerPlaySound` is on and a haptic **only if** `restTimerVibrate` is on. With both off, the screen changes completely and says nothing.
- An exercise change says nothing.

**Fix**: post `AccessibilityNotification.Announcement` at each of these points. It is spoken only while VoiceOver is running, so sighted users are unaffected:
- On log: "Set 2 logged. Rest 1 minute 30."
- In `announceRestCompletion`, regardless of the sound and haptic settings: "Rest over. Next: set 3, 100 kilograms, 5 reps."
- On exercise change: "Incline Bench Press, exercise 2 of 5."

Use `.accessibilitySpeechAnnouncementPriority(.high)` on the AttributedString for rest end. Reuse the pattern already in `+Finish.swift:56`.

**S2. The custom keypad works but gives no feedback to a VoiceOver user.** WCAG 4.1.2, 3.3.2.
- `SetKeyboardTextField.swift:117-125` returns `false` and sets the text through `updateUIView`. UIKit's typing echo therefore never fires. A digit press speaks the key's label ("1") but never the field's new value.
- The stepper buttons "Decrease/Increase weight" (`SetKeyboardView.swift:53,75`) and the chips (`:156-173`) change the weight silently.
- The keys lack `.isKeyboardKey` (`:226-257`), so VoiceOver's touch-typing mode (lift to type) does not apply.
- "Done" (`:196`) **logs the set** through `SetTrackerRowPresenter.offerCompletion` (`SetTrackerRowPresenter.swift:304-310`). Its label says only "Done", which is an unexpected action for something named that way.
- First-key-replaces behaviour (`replacesOnNextKey`) is invisible to a VoiceOver user.

**Fix**:
- Add `.accessibilityAddTraits(.isKeyboardKey)` to the digit, decimal and delete keys.
- After `type`, `backspace`, step and chip actions, announce the new value: "102.5 kilograms" or "6 reps".
- Make the stepper row a single element with `.accessibilityAdjustableAction` and value "102.5 kilograms", which is the native pattern.
- Give Done a hint, "Logs the set when it is filled in", or relabel it "Log set" when the set is ready.

*(verify)* how VoiceOver moves between the text field and the input view on a device.

**S3. At AX5 the fixed chrome crowds out the content, and key text clips.** WCAG 1.4.4, 1.4.10.
- The progress header is a `safeAreaBar` with no cap (`WorkoutTrackerView.swift:55-57, 126-147`). Two `.caption` texts sit side by side at about 40 pt, so they wrap onto several lines and stay pinned on screen.
- The call to action has `lineLimit(2)` at body size, about 53 pt at AX5 (`:92`). "Log set 2 · 102.5 kg × 10" needs about 3 lines, so the figures, which are the useful part, are truncated.
- The Skip Rest row puts the label, a ticking `Text(timerInterval:)` and "+15s" in one HStack (`:64-86`), which cannot fit at AX5.
- `InlineRestTimerRow.swift:46`: `.fixedSize()` on "Rest: 1:27/1:30" next to a ProgressView overflows the row.
- `SetTrackerRowView.swift:177-185`: the set label (`.caption`) grows, but the circle is a fixed 36 pt inside a 44 pt frame, so "1L" clips.
- `SetKeyboardView.swift:36` caps the keyboard at `.xxLarge` with no Large Content Viewer.
- Rough budget on iPhone 17 *(verify)*: chrome takes about 400 pt and content gets about 380 pt, which is under two stacked rows. With the keyboard up, the edited row can sit under the progress bar.

**Fix**:
- At `isAccessibilitySize`, move the progress counts into the list as its first row, or stack them with `ViewThatFits` and cap them at `.accessibility1` with `.accessibilityShowsLargeContentViewer()`.
- Remove the 2-line limit on the call to action, or use `ViewThatFits` with a short form, "Log 102.5 × 10".
- At accessibility sizes, give the rest row and the Skip Rest row a vertical layout, and drop `.fixedSize()`.
- Size the set circle with `@ScaledMetric`.
- Add `.accessibilityShowsLargeContentViewer()` to the keypad keys and chips, as the system keyboard does.

**S4. Contrast failures that the audit's blanket `.contrast` exclusion hides.** WCAG 1.4.3, 1.4.11. Light mode:
- Warm-up "W": `.warmup` orange text on a 15 % orange fill, caption 12 pt, about **2.0:1** (`SetTrackerRowView.swift:176-183`).
- Rest "Ready": `.success` green, caption semibold, about **2.2:1** (`InlineRestTimerRow.swift:24-26`). This is the visual rest-over cue.
- Keypad "Not loadable": `.danger` red at 15 pt on `.regularMaterial`, about **3.5:1** or lower (`SetKeyboardView.swift:99-100`).
- Current-row indicator: a 15 % accent tint (`Palette.swift:42`) plus a 1 pt `.separator` outline (`SetTrackerRowView.swift:97-101, 251`). Both are well under the 3:1 non-text minimum. The full-strength text on the current row versus muted text on upcoming rows partly rescues it.

**Fix**:
- For any text on a tint, use `.primary` for the text and keep the colour on an icon. The plates line already does this at `SetTrackerRowView.swift:66-74`.
- Draw the current row's outline in `.tint` at 1.5–2 pt.
- When `colorSchemeContrast == .increased`, raise the tint opacity.

**S5. Voice Control cannot reliably say the names of the key controls.** WCAG 2.5.3 Label in Name, 2.4.6.
- The Skip Rest name includes the ticking timer (`WorkoutTrackerView.swift:68-71`).
- The log button's name changes with every keystroke (`:91`).
- "+15s" is shown, but its spoken name is "Add 15 seconds" (`:80-84`).
- "Complete set", "Weight, kilograms" and "Reps" are identical on every row (`SetTrackerRowView.swift:213-227`, `SetTrackerRowPresenter.swift:234`), so "Tap Complete set" always brings up numbered disambiguation.

**Fix**:
- Skip Rest: `.accessibilityLabel("Skip rest")` with the time moved to `.accessibilityValue`.
- Add `.accessibilityInputLabels`:
  - Log button: `["Log set", "Log", "Next", "Finish"]` as appropriate.
  - +15s: `["Plus 15", "Add 15 seconds"]`.
- Include the set number in row control names: "Complete set 2", "Set 2 weight".

### Moderate

**M1. Up Next reordering relies on gestures.** WCAG 2.5.1, 2.1.1.
- `WorkoutTrackerView.swift:199-214, 256-269` offers edit-mode drag handles and a long-press context menu.
- Whether VoiceOver surfaces the context menu in its Actions rotor, and whether the List reorder control offers move up/down, is OS-dependent *(verify)*.
- **Fix**: add `.accessibilityAction(named: "Do Next")`, `"Do Later"`, `"Move Up"` and `"Move Down"` on each Up Next row. They appear in the VoiceOver Actions rotor, the Switch Control menu and Voice Control's "show actions", and need no handles.

**M2. No Magic Tap and no Escape.**
- The primary action is the last element in reading order, after Up Next and Completed.
- **Fix**: on the List:
  - `.accessibilityAction(.magicTap) { presenter.runningRestEnd != nil ? onSkipRestPressed() : onPrimaryActionPressed() }`. A two-finger double-tap then logs or skips from anywhere, the way it plays and pauses media.
  - `.accessibilityAction(.escape) { presenter.minimizeSession() }` for the full-screen cover.

**M3. Text below 11 pt.**
- `SetTrackerView.swift:276-280`: the column headers are `.caption2` (11 pt) with `.minimumScaleFactor(0.6)`, so they can reach **6.6 pt**. A long localized header in a 50 pt column will shrink this way; Spanish "Done" is "Listo", and other long strings exist.
- `SetKeyboardTextField.swift:78-79`: `adjustsFontSizeToFitWidth` with `minimumFontSize = 9` shrinks the weight to 9 pt in the 70 pt column at large non-AX sizes.
- **Fix**: set a minimum scale factor of no less than 1.0 (or remove it) and let headers wrap. Set `minimumFontSize = 11`, or widen the column.

**M4. A set row is 5–6 separate stops, and the "Last" column is unexplained.** WCAG 1.3.1.
- The Prev cell reads "100 kg × 5" as "100 kilograms times 5", with nothing tying it to the "Last" or "Auto" header (`SetTrackerRowView.swift:374, 423-432`).
- "RIR 2" is read letter by letter *(verify)*.
- "Next to log" is the value of the warm-up toggle *menu* (`:163-193`). Activating it opens a menu, not a log.
- **Fix**:
  - Wrap each row in `.accessibilityElement(children: .contain)` with the label "Set 2, next to log" (or "logged", or "upcoming"), so the Containers rotor jumps by set.
  - Prev label: "Last time: 100 kilograms, 5 reps, 2 in reserve".
  - Set menu hint: "Set options".
  - Hide the static "Set", "Done" and "Reps" headers from VoiceOver; each cell already names itself.

**M5. Correcting a set is risky.**
- On a logged row, "Set completed" un-logs the set on activation, with no hint and no announcement (`SetTrackerRowView.swift:346-363`, `SetTrackerRowPresenter.swift:44-75`). Un-logging also cancels the rest.
- A trailing full swipe deletes a set, including a logged one, with no confirmation or undo (`:103-105`). This is a hazard for tremor and for one-handed thumbs.
- A logged warm-up cannot be corrected at all, because it is removed (`SetTrackerView.swift:76`).
- **Fix**:
  - Hint "Double-tap to mark as not done" and announce "Set 2 unmarked".
  - Set `allowsFullSwipe: false`, or offer undo through a toast.
  - Keep logged warm-ups visible, muted.

**M6. The quick-finish announcement can contradict the screen.**
- `+Finish.swift:56` says "Finish Workout is available." With `restBetweenExercises` on, the last set still starts a rest (`RestDurationRules.swift:88-90`), so the bar shows **Skip Rest** (`WorkoutTrackerView.swift:61`) *(verify)*.
- **Fix**: skip the rest after the workout's final set, or announce "All sets complete. Skip rest, then Finish Workout."

**M7. One-handed, left-handed reach.**
- Early Finish and Pause are only in the top-right "Workout options" menu (`WorkoutTrackerView.swift:349-396`).
- The exercise menu is at the top right of the card.
- On the keypad, Next, Done and + sit in the right-hand column (`SetKeyboardView.swift:177-207`). "+15s" is at the far right.
- The full-width bottom button is good.
- **Fix**: offer a mirrored keypad, or a full-width Done row under the digits. Put Pause and Finish in a context menu on the call to action as well.

**M8. The audit test hides more than it says.** `WorkoutTrackerUITests.swift:94-112`
- It runs once, at the default size, in one state (resting after one set). The progression note is dismissed first (`:97`). The keyboard is never open and Up Next is not in edit mode. Off-screen content is never audited.
- `.dynamicType`, `.textClipped` and `.contrast` are excluded **suite-wide**. The justification cites screenshots from `testDarkModeAtALargeTextSize`, which:
  - runs at `AccessibilityL`, which is **AX2**, not AX5;
  - in dark mode, where the orange and green pass;
  - and asserts nothing.

  So the exclusions hide S3 and S4 now, and any regression later.
- `issue.element == nil && .hitRegion` treats *every* unnamed hit-region issue as the toolbar's.
- **Fix**:
  - Keep all audit types and filter by element in the handler: return `true` only for the known false positives, matched by label or identifier.
  - Add audit passes:
    - with the keyboard open;
    - with the rest over ("Ready" shown);
    - at `UICTContentSizeCategoryAccessibilityXXXL`;
    - in light mode with a warm-up row on screen.
  - Tighten the hit-region filter to elements whose frame lies in the navigation bar.

### Minor
- `InlineRestTimerRow.swift:44-56`: "Rest: 1:27/1:30" is read literally ("slash"). Use label "Rest" with value `Text(timerInterval:)` plus "of 1 minute 30".
- `WorkoutTrackerView.swift:150-166`: the custom principal title is not a header, and "· 32:15" reads ambiguously. Add `.accessibilityAddTraits(.isHeader)` and give the elapsed time a spoken-units label. The cap on the navigation bar is the system's, and adding the Large Content Viewer is the correct HIG mitigation. Keep it.
- `SetKeyboardTextField.swift:80`: the placeholder "-" is read as "hyphen". Set `accessibilityValue` to "empty" when there is no text.
- `SetTrackerView.swift:310-329`: the Last/Auto toggle should expose its state, e.g. value "Showing last session".
- `SetTrackerRowView.swift:35`: the input cells are 35 pt tall. That passes WCAG 2.5.8 (24 pt) but is below the HIG's 44 pt. "Plates" and "Use … kg" bordered buttons are about 34 pt.
- `ProgressionNote.swift:29`: "Tap to dismiss" is fine visually. Add `.accessibilityInputLabels(["Dismiss note", "Smart Progression"])`.

## What's working well (keep it)
- Reduce Motion is respected everywhere. `reducedMotionAnimation` is used throughout, the bottom bar's transition falls back to opacity, and the row-highlight animation is gated.
- **Colour is never the only signal.** Warm-ups show "W". Done, ready and not-ready use three different shapes (`checkmark.circle.fill`, `circle`, `circle.dashed`). Plate warnings pair an icon with text. Completed exercises carry a "Done" label. The superset chip has text. The remaining colour problem is **contrast**, not hue.
- Real 44 pt frames on the set number, Done and Prev cells, and keypad keys of 46 pt or more that scale.
- The stacked two-line row at accessibility sizes. Images hidden from VoiceOver. Every icon-only control is labelled. Swipe actions are mirrored in a context menu. Hardware keyboards go through the same input path.
- The quick-finish announcement is the right pattern. It only needs to spread to the other state changes.

## Paged layout (MacroFactor-style) versus this vertical list

- **VoiceOver: about even, and worse unless the extra work is done.**
  - Each page gives a shorter, cleaner reading order, and three-finger swipes give "page 2 of 6".
  - Other exercises become a thumbnail strip, which needs labelled buttons and custom actions to reorder.
  - Content on other pages cannot be reached by swiping element to element.
  - Auto-advancing after the last set replaces the *whole* page, so C1 gets worse, not better.
  - If built, it needs `accessibilityScrollAction` / page semantics, a screen-changed or focus move on each page change, and the same Magic Tap.
- **Switch Control: worse.**
  - Horizontal paging means using scroll actions from the switch menu.
  - Paging horizontally while scrolling vertically within a page creates nested scroll directions.
  - Thumbnails are small scan targets.
  - The vertical list keeps everything in one linear, scannable order and has no hidden content. Scans are longer, which grouping and Magic Tap-style shortcuts mitigate.
- **Others:**
  - Voice Control can say "swipe left", but each thumbnail needs a name.
  - At AX5 a thumbnail strip cannot carry readable text.
  - Accidental page swipes hurt motor and one-handed users.
  - Page transitions are motion and would need a cross-fade under Reduce Motion.

**Verdict**: keep the vertical layout. The problems are focus and announcements, which a paged design would make worse.
