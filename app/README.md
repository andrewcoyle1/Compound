## Getting Started 🚀

This project contains 3 flavors:

- development
- staging
- production

To run the desired flavor either use the launch configuration in VSCode/Android Studio or use the following commands:

```sh
# Development
$ flutter run --flavor development --target lib/main_development.dart

# Staging
$ flutter run --flavor staging --target lib/main_staging.dart

# Production
$ flutter run --flavor production --target lib/main_production.dart
```

_\*Compound works on iOS, Android, Web, and Windows._

### Mixpanel token

The development flavor sends events to Mixpanel only when it is given the project token, which
must never be committed (the repo is public). Put it in `app/dart_defines.json`, which is
gitignored:

```json
{ "MIXPANEL_TOKEN": "<the token from Keys.swift>" }
```

and run with `--dart-define-from-file=dart_defines.json`. Without it, Mixpanel is off and Firebase
Analytics, Crashlytics and the console still log.

### RevenueCat keys

Subscriptions go through RevenueCat (`packages/purchases_repository`), with the Firebase uid as the
app user id, as in the Swift app. RevenueCat gives each platform app its own public SDK key, so
there are two, in the same gitignored `app/dart_defines.json`:

```json
{
  "MIXPANEL_TOKEN": "…",
  "REVENUECAT_APPLE_API_KEY": "appl_…",
  "REVENUECAT_GOOGLE_API_KEY": "goog_…"
}
```

The app passes the one for the running platform to `RevenueCatPurchasesRepository.init`. They
belong to the RevenueCat apps for the Flutter bundle ids (`com.andrewcoyle.compound.flutter.dev`
on iOS, `com.andrewcoyle.compound.dev` on Android), not the Swift app's `revenueCatDevAPIKey`.
The development flavor starts RevenueCat only when the running platform's key is set, and
otherwise uses the premium `FakePurchasesRepository`, so nothing reaches RevenueCat without a key.
The app logs RevenueCat in with the Firebase uid at every sign-in (`AppBloc`).

The staging flavor uses `FakePurchasesRepository` and needs no key. Two defines reach every
paywall state:

- `--dart-define=STAGING_PREMIUM=false` starts without a subscription. The sample user reaches the
  tabs (the coach's See Plans and Settings › Subscription open the paywall); signing in again, or
  an account still in onboarding (`STAGING_ONBOARDING`), is held at "Why Subscribe?".
- `--dart-define=STAGING_PURCHASES=cancelled,pending,failed,owned,loadFailed,noProducts` (any
  of them, in order): what the next purchases and restores do, and whether the plans load.

## Running Tests 🧪

To run all unit and widget tests use the following command:

```sh
$ very_good test --coverage --test-randomize-ordering-seed random
```

## Working with Translations 🌐

This project follows the [official internationalization guide for Flutter][internationalization_link] using [ARB files][arb_documentation_link] for translations.

### Adding Strings

1. To add a new localizable string, open the `app_en.arb` file at `lib/l10n/arb/app_en.arb` and add a new key/value pair with the relevant description (optional):

```arb
{
    "@@locale": "en",
    "counterAppBarTitle": "Counter",
    "@counterAppBarTitle": {
        "description": "Text shown in the AppBar of the Counter Page"
    },
    "helloWorld": "Hello World",
    "@helloWorld": {
        "description": "Hello World greeting."
    }
}
```

1. Use the new string:

```dart
import 'package:compound/l10n/l10n.dart';

@override
Widget build(BuildContext context) {
  final l10n = context.l10n;
  return Text(l10n.helloWorld);
}
```

### Adding Supported Locales

Update the `CFBundleLocalizations` array in the `Info.plist` at `ios/Runner/Info.plist` to include the new locale.

```xml
    ...

    <key>CFBundleLocalizations</key>
	<array>
		<string>en</string>
		<string>es</string>
	</array>

    ...
```

### Adding Translations

1. For each supported locale, add a new ARB file in `lib/l10n/arb`:

```
├── l10n
│   ├── arb
│   │   ├── app_en.arb
│   │   └── app_es.arb
```

1. Add the translated strings to the new `.arb` file:

`app_es.arb`

```arb
{
    "@@locale": "es",
    "counterAppBarTitle": "Contador",
    "@counterAppBarTitle": {
        "description": "Texto mostrado en la AppBar de la página del contador"
    },
    "helloWorld": "Hola Mundo",
    "@helloWorld": {
        "description": "Saludo Hola Mundo."
    }    
}
```

### Generating Translations

To use the latest translations changes, you will need to generate them:

```sh
flutter gen-l10n --arb-dir="lib/l10n/arb"
```

Alternatively, run `flutter run` and code generation will take place automatically.
