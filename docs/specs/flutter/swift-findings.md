# Swift app findings from the Flutter port

Writing contracts and porting logic means reading every Swift model and rule closely. These issues
were found along the way. **None was changed**: Swift app code is outside the Flutter run. Each
needs the owner's decision.

- **FoodLogSettings decodes strictly (synthesized Codable).** Fields added later (`favourite_food_ids`, `favourite_recipe_ids`, `hide_food_details`, `hide_empty_hours`) make documents written before them fail to decode. iOS then quietly shows defaults, and the user's next save overwrites their old settings. Found by M2-3 (#91). The fix is a lenient `init(from:)` in Swift, which is outside the Flutter run.
- `firestore.rules` has a stale comment giving the meal path as `meal_logs/{dayKey}/meals/{mealId}` (M2-3).
- SetTarget: a null `set_type` reads as standard, but a *missing* one fails the decode. Sessions before 30 Sep 2026 carry `training_program_id`, which Swift no longer reads (M2-1).
- **Clearing a body value never reaches Firestore.** `BodyMeasurementEntry.withCleared(…)` is saved as a merge, and a merge skips nil (omitted) fields, so the old value comes back on the next sync. This breaks deleting a weigh-in on Scale Weight, Weight Trend and Weigh-in Consistency, clearing values on the measurement detail screens, and the HealthKit day-clearing import. Found by M2-5 (#94). The fix is in Swift: write `FieldValue.delete()` for cleared fields, or save without merge. Outside the Flutter run.
- **Swift sends `uauth_email` (and display name) as analytics parameters and user properties to Firebase Analytics and Crashlytics.** Google Analytics' terms forbid personal data. The Flutter app sends name and email to Mixpanel's identify only. Found by the analytics slice (#96). Worth fixing in Swift.
- **The Weight Trend chart plots kilograms under a pounds label** for users who chose pounds. Found by M2-6 (#98). The Flutter app converts both series to the user's unit.
- **User-created exercises are readable by every signed-in user.** `firestore.rules` lets any authenticated user read `exercise_templates`, where Swift keeps users' own exercises. Found by M3-1 (#99). This is a rules decision for the owner.
- **`WorkoutSettings` decodes strictly** (synthesized). A document missing any non-optional key fails silently and shows defaults; this is the same class of bug as FoodLogSettings.
- **Clearing an exercise note or rest override leaves the old value in Firestore,** because saves merge. Same class as the body-value bug.
- **`GoalManager.updateGoal` merge-saves the goal,** so changing the objective leaves both objective keys in the stored map (`{"loseWeight":{}, "gainWeight":{}}`). Found by M3-3 (#100).
- **Some old saved foods silently vanish on iOS.** `FoodModel` decodes strictly, so two kinds of food fail to decode and are dropped: foods from before 13 Mar 2026 that have only the flat nutrient fields, and foods saved on 12–13 Mar 2026, whose nutrients were stored as a key/value array. Found by M3-2 (#102).
- **A food can be saved without an owner, and the save is then refused.** `FoodModel.authorId` is optional, but the rules require `author_id`. If no user is loaded, the label-scanner save fails.
- **Removing a nutrient from a saved food never reaches Firestore.** A merge save combines nested maps key by key. Same class as the body-value bug. Dart matches it for now. Found by the food data slice (#105).
- **A workout save that only succeeds on retry never writes the weekly streak.** `plannedSession` also rounds weights on a different gym from the one the session is built on. Found by the tracker engine (#107).
- **A second logging break never opens.** The merge keeps the old `end_date` (`NutritionStrategyManager.swift:109-114`). "Clear" on the expenditure calculation start date never reaches Firestore either (`ExpenditureSettingsPresenter.swift:115-119`). Found by M4-a (#108). Flutter uses `FieldValue.delete()` for both.
- **The comment and notification create rules accept any keys,** so a client can create a comment with fake likes. `ShareModel` reads an unknown kind as a template. Found by M5-a (#112).
- **Social:** `markAllRead` fails with more than 500 unread notifications, because it commits a single batch. The notification rules let the actor change any field of a notification they wrote. Followers are silently capped at 200. New-notification listening compares against the device clock. Found by M5-b (#115).
- **The push token stays on the device's last account after sign-out,** so after a second account signs in on the same device, it receives the first account's pushes. Separately, `knownPendingIDs` omits the idle-workout reminder, so each launch's sweep withdraws it. Found by M4-c (#117).
- **The coach reports the 5-a-minute burst refusal as the daily limit** (`coachError`), and `CoachManager` then shows 0 messages left. Found by M5-c (#118).
- **Apple Health:** editing a weigh-in already sent to Health leaves the old value there, and deleting a weigh-in in Compound leaves its Health sample. Found by M5-e (#121).
- **Strava:** `stravaActivityDoc` always writes `total_elevation_gain` (0 when Strava has none), so "no data" and "flat" look the same. The Swift sync loop may not re-check the account after sign-out (unconfirmed). Found by M5-d (#122).
- **Settings saves drop cleared values.** "Off" for superset rest, "Reset Default Timers" and clearing an exercise's rest override never reach Firestore, because the merge keeps nested map keys and skips nil. Edit Profile shows the sign-in provider's name instead of one the user edited, and saves today's date as the date of birth for anyone who never gave one. Found by Settings part 1 (#128).
- **Social screens:** mutual-follower avatars fall back to the "SplashScreen" image (`SocialProfileView.mutualFollowersImageCircle`); a comment made only of line breaks enables a Send that does nothing (`CommentsView` trims `.whitespaces`, the presenter `.whitespacesAndNewlines`); name search queries only `submitted_first_name`, so people named only by their sign-in provider can't be found. Found by Social part 1 (#131).
- **Kilograms whatever the unit:** the Weekly Review's trend weight (`WeeklyReview.weightText`) and the Workouts screen's volume rows (`WorkoutEntry.displayValue`). Found by Progress part 2 (#133).
- **Programs:** `MacrocycleManager.save` merges, so `advanced()`'s nil `startMicrocycleIndex` never clears and the next mesocycle shows the old join point's earlier microcycles as "not tracked"; `ActiveMesocyclePresenter.run(for:)` drops `firstMicrocycleIndex`, so the Training tab ignores where the user joined while Today honours it; `Mesocycle.init` replaces an empty `workoutTemplates` with defaults; `PeriodisationPhase.label` and `DeloadType.title` are hard-coded English, and the Spanish "Complete" status reads "Completar" (a verb). Found by Programs part 1 (#134).
- **Mesocycle editing:** the colour and icon editor never shows the current colour as selected; the default colour's stored hex depends on light or dark mode; Settings' Activate accepts a mesocycle of rest days only; the mesocycle-name sheet is titled "Rename Day"; edits never update `date_modified`. Found by Programs part 2 (#136).
- **Progress:** many measurement strings are English-only in Spanish (`BodyMeasurementKind.navigationTitle`, `fieldLabel`, `emptyStateMessage`, and `MetricConfiguration` empty states and add titles passed as `String`); the weekly target grid draws `planDays[idx]` in column `idx` while columns start on `Calendar.firstWeekday`, so a Sunday-first week shows Monday's target under Sunday; `HabitsPresenter` counts weigh-ins, not days, so two in a day count twice. Found by Progress part 3 (#137).
- **Workout editor:** `WorkoutTemplateManager.saveWorkoutTemplate` merges, so a cleared description, picture or gym never reaches Firestore (the editor never clears one today); `DefineWorkoutRules.supersetLetters` numbers supersets past Z while the detail screen's `WorkoutTemplateExercise.supersetLetters` stops, so they can disagree on a 27th superset. Found by the workout editor (#138).
- **Gym profiles:** Create Gym Profile from Choose Gym Profile, then Continue, sends a user who finished onboarding to the Onboarding Completed screen, because `GymProfilePresenter.onContinuePressed` routes by `inferredOnboardingStep` (`.complete`). Add Body Weight accepts 0. A user's own machine copies the first catalogue machine's description and image. Found by the gym editor (#140).
- **Foods:** deleting a food leaves its id in `favourite_food_ids`. A serving with no weight is stored as if its figures were per 100 g. Found by nutrition library part 1 (#142).
- **Create Exercise:** `testTheSecondMetricAloneIsEnoughToContinue` has no `#expect`, so it checks nothing; the flow's two delegates' `eventParameters` always return nil. Found by Create Exercise (#141).
- **Recipes:** Create & Add for recipes is unreachable (`CreateRecipePresenter` never passes the callback to Preparation); Recipe Start lists ingredient amounts as written, ignoring the servings chosen on the detail screen; deleting a recipe leaves its id in `favourite_recipe_ids`; an ingredient's + for a volume food with a portion weight uses the grams as millilitres. The ingredient picker never marks foods already chosen (`selectedFoods` is unused). Found by nutrition library part 2 (#145).
- **Notifications inbox:** Swift marks everything read right after loading, so the unread style shows only for an instant (ported as is); `SettingsPresenter.onNotificationsPressed` has no caller. Found by the inbox (#144).
- **Sharing:** the shared item shows the template's name twice (title and section header); Weekly Review's Share button is never actually disabled while sharing. Found by Social part 2b (#148).
